# 下一步实施顺序

当前是配置基线整理完成，以下运行验收仍待在真实环境执行。按顺序推进，每阶段通过后再扩展。

| 顺序 | 工作 | 通过条件 |
|---|---|---|
| 1 | 现场盘点与基线安装 | 记录实际版本、MA config entry、房间实体及音频 URI；备份完成；无重复脚本；离线和 HA 配置检查通过 |
| 2 | 单播放器手工工具验收 | status、search_only 正确；搜索无结果不改变队列；播放有实际声音；暂停/恢复/音量执行正确，留轨迹 |
| 3 | 多房间与持久调度 | 两房间独立设短定时；覆盖旧定时；取消不暂停；重启后计划仍在；离线/不可用恢复行为符合说明；无房间命令使用共享缓存；无效房间拒绝 |
| 4 | DeepSeek 文字 Assist | 准确点歌、歌手泛听、音量+定时组合、收藏逐项有工具证据；缓冲不误报无结果；失败不虚构成功；未知房间不擅自切换 |
| 5 | 语音输入与 Piper | 普通话先验收；比较远程 Whisper/云 STT，分别记录准确率和延迟；确认 Piper 在实际终端可听，预先定义可接受延迟目标 |
| 6 | ESPHome 常开终端 | 核对实际板型/引脚/音频 codec 支持后实现唤醒、录音、播报与待机背光；终端断网重连可恢复；未先验硬件型号不写通用固件 |
| 7 | 方言和体验优化 | 泉州话与普通话混合测试集，按实测选模型/云服务，未达标再评估训练；情绪音色与唤醒误触单独评估 |
| 8 | 音源与维护能力 | 先证实 lx_server/provider 支持按请求指定源再做权重/兜底；后续考虑每人房间记忆、计划历史清理、耗时指标和长期恢复策略 |

## 最小验收表

| 场景 | 预期 |
|---|---|
| “卧室找一下周杰伦，先别播放” | search_only；队列、音量、房间缓存均不被播放逻辑改变 |
| “一楼放轻音乐，音量15%，两分钟后停” | 单次组合请求；目标正确；真实播出；计划只作用于一楼 |
| “取消一楼定时” | 清除相应计划但不暂停 |
| “继续播放” | 使用最近成功操作的房间；不按 bedroom 旧实体 ID 猜房间 |
| 播放器不可用 / 歌曲仍缓冲 | 明确失败或加载；不重复搜索替换队列，不虚构成功 |
| 收藏按钮不存在 | 说明不支持，不操作其他设备 |
| HA 重启时计划已经逾期 | 恢复后补暂停，记录实际延迟；不能宣称离线准时执行 |

原迁移说明有“保存成功、未主动播放测试”的明确边界，本路线不将其升级成验收通过。
